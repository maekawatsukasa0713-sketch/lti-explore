## 現在の状態

既存の探究アプリの画面を使い、Supabase Authとデータ保存に接続したソースです。
サイトへのデプロイはしていません。以前の単一TSXファイルの代わりに、このフォルダ全体を使用してください。

- 接続先の組織はFreeプランと確認済み。新規の有料プロジェクトは作成していません。
- DBに学校、利用者プロフィール、アプリデータ、非公開PDFバケットと権限設定を作成済み。
- 利用者と学校はまだ登録していません。テスト用データはトランザクションをロールバックし、残していません。
- `002-private-threads.sql` は自動承認レビューで拒否されたため **未適用**。公開論文と非公開の教員・運営連絡を分離するための追加変更です。ユーザーの承認を得た後に適用・検証する必要があります。自動で適用するコードは含めていません。
- `schema.sql` は基本構成の参照用です。既存プロジェクトに再実行しないでください。
- `003-account-provisioning.sql` は反映済み。`lti-accounts` Edge Functionも配置済みです。
- AI提供元は接続していません。AIボタンは未設定表示となり、論文をAIへ送信しません。

## 起動

Node.js 20.19以降の環境で、このフォルダ内で実行します。

```sh
npm install
npm run dev
```

ビルドは `npm run build`。Next.jsへ組み込む場合はApp.tsx・cloud.tsx・supabase-config.tsを同じディレクトリに置き、必要なnpm依存とTailwind設定を引き継いでください。
公開用URLの設定、認証メールの配送、最初の管理者登録、追加DB変更が完了するまで本番利用はしないでください。

## 認証と管理者の初期設定

認証はSupabase Authを使用します。LTIはメール、生徒・教員は学校IDとログインIDを使用できます。アプリのDBにパスワードを保存しません。
新規登録時のプロフィールは「生徒・未承認」で、学校も未設定です。自己申告の権限を信用しません。

1. 起動URLをSupabase AuthenticationのURL Configurationに登録します。確認・再設定メールがこのURLに戻る必要があります。
2. 本人がアプリでアカウント登録・メール確認を行います。
3. 最初のLTI管理者だけは、本人のAuth利用者IDを確認して管理者権限を設定する必要があります。自動で最初の登録者を管理者にはしません。設定後は認証アプリの登録を行います。
4. その後は画面右下の「学校・利用者管理」から、学校追加・生徒／教員の一括発行・再発行・利用停止を行えます。

認証メールの標準配信には制約があります。複数校での利用前に送信設定（SMTP）、メール認証、再設定導線を実機確認してください。

## 学校ID・生徒IDと初期パスワード

LTIの「学校・利用者管理」画面で学校名を入力すると、学校IDを自動発行します。
学校・生徒または教員・人数を選ぶと、1回20人までAuthアカウントを発行します。
学校ごとのIDは s00001 / t00001 のように自動採番します。各人に異なるランダムな初期パスワードを生成します。

発行直後に学校ID・ログインID・初期パスワードの一覧を表示し、配布用CSVを保存できます。
この一覧は画面のメモリにのみ保持し、パスワードをアプリDBやブラウザの保存領域に記録しません。
LTIから担当教員へ安全に渡し、各本人に本人の分だけ配布します。控え忘れ・紛失時は再発行します。
変更後のパスワードはLTI・教員にも表示しません。

- 生徒・教員は「学校IDでログイン」を使います。実際のメールアドレスの登録・受信は不要です。
- Auth内部のメール形式識別子はIDから一方向に生成する技術上の識別子で、メール送信には使いません。
- 初期パスワードは7日間有効。最初に8〜128文字の新しいパスワードへ変更します。
- 初回変更前はDBとファイルにアクセスできません。フロントの表示を飛ばしても制限が残ります。
- 初回変更・再設定は現在のパスワードを確認し、古いセッションからのデータアクセスも拒否します。
- 学校用アカウントの再発行は、本人確認をしたうえでLTI管理者が行います。
- LTI管理者はTOTP認証アプリによる二段階認証が必須です。メールやSMSは使いません。
- 教員・生徒は任意で二段階認証を設定できます。一度登録した場合はコードが必要になります。
- 認証アプリ端末を紛失した場合の本人確認・復旧は、Supabaseの管理運用で対応が必要です。一般のパスワード再発行では二段階認証を解除しません。
- ID発行予約はDBで処理し、同じ要求IDの再実行を拒否します。途中失敗や通信断では利用者一覧を確認し、必要に応じて初期パスワードを再発行します。初期パスワードの再取得はできません。
- CSVから既存名簿を取り込む機能はまだありません。今回のCSV機能は配布用の出力です。

アカウント発行関数は本人のJWTをAuthのgetUserで検証し、DBで管理者権限・初回変更完了・MFAを再確認します。
Edge Functionのゲートウェイの旧JWTチェックは使用せず、関数内部の認証で検証しています（verify_jwt=false）。
管理者用秘密鍵はサーバー環境変数から読み、配布ファイルには含めていません。

## 保存するデータ

- 課題、個別の提出物、論文と公開申請、教材、イベント、お知らせ、教員フィードバック、参考文献とメモ。
- 提出物は課題の共有データから分離し、生徒本人・同じ学校の教員・LTI管理者が閲覧します。担当教員単位に絞る仕様は未実装です。
- 参考文献は本人とLTI管理者が閲覧可能。ほかの生徒や教員には公開しません。
- 論文は承認待ち・差し戻し等を区別し、公開承認はLTI管理者のみ実行できます。
- PDFは10MB以内。非公開バケットに保存し、認証付きダウンロードで表示します。
- 教材スライド画像は従来形式を維持し、教材データに含めてDBへ保存します。1教材は約2MB以内です。
- 画面のメニュー順だけはブラウザに保存します。以前の平文パスワードやローカルのサンプルデータはクラウドへ移行しません。
- 更新ボタンで他端末の変更を取得します。リアルタイム購読は未実装。
- バージョン番号を比較し、競合があれば保存せず再読み込みを促します。複数の保存処理を同時には実行しません。
- 旧画面の完了メッセージより、接続層の保存エラー表示を優先してください。
- 提出物がある課題は削除を止めています。編集を利用してください。
